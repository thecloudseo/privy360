# Integration, AI and extension execution contracts

## Connector invocation

Input: `{runId,connectorId,adapterVersion,operation,workItemId,scopeRef,inputRef,idempotencyKey,deadline}`. Server loads trusted tenant/actor mode and capability from work item and connection; queue payload cannot supply authority. Adapter receives a short-lived secret handle for one connector slot, permitted endpoint set and exact operation scope. It cannot list vault secrets, tenants, buckets or unrelated source records. API process never imports untrusted plugin code.

Output: `{runId,status:SUCCEEDED|FAILED|UNKNOWN,observedAt,checkpoint?,recordsRef?,proofDigest?,providerReceipt?,errorCode?}` validated against operation schema. Owner module revalidates records and target scope before storing. Raw remote error bodies are not logged. Checkpoints are opaque encrypted tenant-owned state, bound to adapter version/query digest; retry cannot change scope. Pagination has max pages/bytes/deadline and rate budget. No continuing a checkpoint under a different tenant/credential/capability.

Operations: discover_metadata, search_subject_references, collect_evidence, write_approved_change, delete_approved_targets. Each is separately granted; none implies another. Deletion runner obtains approved plan digest and target lease, checks current hold/tenant/policy, calls provider with stable idempotency key and stores outcome. Timeout after possible side effect=UNKNOWN; query provider status or require human reconciliation, do not claim completion. Webhooks use EVENT_MODEL signed envelopes/inbox dedupe. Outbound message approval is separate from transport capability.

Read-only initial adapters: IAM MFA configuration; cloud encryption metadata; backup success; SIEM logging health. Every adapter must publish permission requirements, source schema, supported versions, freshness semantics, failure classification and evidence-capture method. A provider-specific implementation has its own tests and review, not a generic “connect everything” ticket. Customer-network agent/pull model may be introduced via ADR when inbound connectivity is forbidden; its contract stays one-tenant/capability-scoped with signed work items and no remote shell.

## AI request and model port

AI application request `{taskType,question,contextRefs}` becomes a durable run with original actor/tenant, policy version, purpose, deadline and quota. Policy modes and approved-provider restrictions are in SECURITY_ARCHITECTURE. Provider port receives redacted prompt/context with provenance IDs, model/version, region/profile, maximum tokens, timeout and tool schema subset. It never receives auth tokens, connection credentials or unrestricted database access. Store request/response digests and source references by default; full prompt retention requires a separately approved purpose, classification and short schedule.

Retrieval starts with authorized root resource IDs/scopes, applies tenant/object/classification permission before ranking, and rechecks selected results before prompt assembly. Initial structured queries/full-text search run in PostgreSQL under RLS. Optional pgvector embeddings live in the same tenant-owned embedding_chunks table under FORCE RLS; provider/model dimensions and normalization version pinned. No external shared vector store. Unsupported pgvector deployment falls back to authorized full-text/structured retrieval, not an unscoped external service. Embedding contents are personal data when source is; source revocation/purge invalidates chunks, caches and pending runs.

Model output is `{answer,citations:[sourceId,version,locator],uncertainty,proposals:[toolId,args]}` parsed as untrusted data. Validate citation existence/version and permitted visibility, sanitize rendering and scan for prohibited sensitive fields. A citation existing does not prove model interpretation correct; display advisory status and require human review for legal conclusions. No automatic “compliant” declaration. Missing approved evidence yields inability/uncertainty rather than invented citations.

## Tool policy

Registry entry: tool_id/version, operation schema, required permission, resource resolver, side-effect classification READ/PROPOSE/EXECUTE, data classification, approval requirement, timeout, retry/reconciliation policy. Invoke only through domain ports with current original actor scope. No shell, SQL, arbitrary HTTP, file path or dynamic tool registration from model text. Human approval binds proposal ID, canonical argument digest, tenant, actor, resource versions, allowed action and expiry; any change requires new approval. Always reauthorize at execute. AI cannot create approval records or escalate SYSTEM_POLICY authority.

Forbidden autonomous tools: statutory exemption determination, legal rights rejection, legal compliance declaration, authoritative regulatory mapping publish, regulator breach notification, bulk/destructive deletion. Some can be drafted as human-reviewed proposals through normal modules; AI never replaces legally accountable decision makers. Run cancellation revokes unexecuted proposals; completed irreversible effects require normal incident/reconciliation handling.

## Planned extension contracts

Discovery/classification/lineage observations contain source locator, observed metadata, proposed classification, confidence and provenance; promotion is a reviewed domain command. Sector packs cover government benefits/scholarships/licences/certificates/municipal/examinations/grievance/recruitment/web/public health; BFSI onboarding/KYC/loans/credit/collections/service/marketing/fraud/support/employees/vendors; health registration/appointments/diagnostics/insurance/sharing/research/telemedicine/minors; EdTech registration/parent verification/guardian consent/analytics/video/advertising assessment/erasure. Each pack is a versioned draft template set and questions, not invented legal requirements.

Digital Twin: scenario_schema_version, authorized graph_snapshot_id, policy_bundle_version, hypothetical_changes → findings/impact paths; cannot mutate live state. Privacy CI/CD: external build ref, approved inventory manifest, policy bundle digest → deterministic findings and signed result; client credentials scoped to one project/tenant, no self-approved exception. Consent Manager interoperability: versioned adapter maps verified external subject/purpose/notice/event provenance to canonical ledger; unknown external semantics remain unsupported pending approved protocol/legal review. Advanced AI agents remain bounded sequences of the same tools and approvals.

## Verification

Connector SSRF/rebinding, wrong credential/tenant, replay/checkpoint substitution, malicious response, unsafe deletion retry, disconnected mode and provider outage tests. AI direct/indirect prompt injection, cross-tenant retrieval/cache, hidden prompt/PII requests, forged citations, stale permissions, unauthorized tool calls, SQL/delete/breach-send attempts, evidence manipulation, legal hallucination, cost exhaustion and argument substitution tests. Feature remains disabled until provider policy and applicable human/security gates are approved.
