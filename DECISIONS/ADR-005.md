# ADR-005: Redis as expendable infrastructure

Date: 2026-09-30

Status: Selected for architecture baseline

## Context

Privy360 must implement the full MASTER_SPEC platform across four deployment modes with default-deny security and durable traceability. The bid is an early release milestone only.

## Decision

Redis for bounded cache, rate limiting and revocable session support; not audit/event source of truth.

## Alternatives and rationale

Using Redis as sole durable ledger risks silent loss and inconsistent recovery.

## Consequences and verification

Loss invalidates sessions or throttles conservatively; business history persists in PostgreSQL. Normative details and required tests: [contract](../SECURITY_ARCHITECTURE.md). Applicable approval gates are in [ARCHITECTURE](../ARCHITECTURE.md).

## Revisit trigger

Measured failure to meet security, portability, throughput or regulatory traceability requirements; propose a superseding ADR with migration and compatibility impact before changing this choice.
