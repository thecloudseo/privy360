# ADR-018: Encryption and key separation

Date: 2026-09-30

Status: Proposed — security approval required

## Context

Privy360 must implement the full MASTER_SPEC platform across four deployment modes with default-deny security and durable traceability. The bid is an early release milestone only.

## Decision

Proposed provider-backed envelope encryption, tenant-bound authenticated context, separate data/backup/signing keys.

## Alternatives and rationale

Volume encryption alone does not constrain privileged data access; home-grown crypto is prohibited.

## Consequences and verification

Security approval OPEN-02 required for algorithm/provider profile and production acceptance; no crypto implementation yet. Normative details and required tests: [contract](../SECURITY_ARCHITECTURE.md). Applicable approval gates are in [ARCHITECTURE](../ARCHITECTURE.md).

## Revisit trigger

Measured failure to meet security, portability, throughput or regulatory traceability requirements; propose a superseding ADR with migration and compatibility impact before changing this choice.
