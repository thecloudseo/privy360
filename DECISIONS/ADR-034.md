# ADR-034: Local service vulnerability eligibility boundary

Date: 2026-09-30

Status: Separation of local eligibility and deployable approval approved as a design direction; implementation and policy await final security approval. No vulnerability disposition is approved.

## Context

FOUNDATION-003 supplies an isolated local development service composition. The current official Keycloak image has unresolved High/Critical scanner findings. ADR-007 retains Keycloak as the selected identity product. A local developer must be able to review exact findings without mistaking local use for a production security approval.

## Decision

Local-development eligibility and production/deployable-artifact security approval are separate decisions. The proposed local policy binds immutable image digest, platform, material Compose configuration including mounted contents, complete current scanner/SBOM provenance and individually approved, expiring CVE/package/path dispositions. It defaults to deny. No disposition is active in the repository. Scanner-correction, configuration-specific-nonexposure and residual-risk-acceptance require distinct evidence and review.

The local Compose stack and any local-only disposition are prohibited from staging under production security policy, SaaS production, customer VPC, government/on-premise and signed/offline customer bundles. The existing High/Critical gate remains mandatory for deployable artifacts. Raw scanner findings remain visible; no blanket exclusions, severity changes or ignore-unfixed option are permitted.

An approved local disposition would be a bounded permission to use synthetic local services, not a finding-free result. It would never be production, customer, government or release-bundle approval. Changes to the image digest, platform, package path or material configuration invalidate it. Security and Chief Architect review must approve each occurrence with protected independent provenance, accountable owner, tracked remediation obligation, valid review deadline and expiry. The policy implementation and individual records still await final security review.

## Consequences

Development remains blocked for local eligibility until exact records are approved with verifiable provenance or scans pass. The proposed FOUNDATION-003 verifier requires an exact signed local approval manifest and an independently protected trust record outside this repository. No real reviewer key or trust record is provisioned, and no disposition is approved. Approval strings alone deny. Production review remains independent and unchanged. Future publishing/signing/deployment entry points must use rendered artifact validation and the independent production scanner gate together; none exists in this ticket. Docker-level controls cannot prove absence of host tunnels, real data entry or post-start Keycloak administration; these are operational prohibitions and review items.
