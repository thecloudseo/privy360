# ADR-033: Tenant-scoped search and vector retrieval

Date: 2026-09-30

Status: Selected for architecture baseline

## Context

Evidence search, AI retrieval and future discovery need ranking without creating a second authorization boundary or mandatory external service.

## Decision

Start with PostgreSQL structured/full-text queries under FORCE RLS. If embeddings are enabled, pgvector stores vectors on tenant-owned embedding_chunks with pinned model/dimensions and current resource authorization. Use full-text fallback when extension support is absent. No shared external vector store or model-side filtering for tenant isolation.

## Alternatives and consequences

External search/vector engines can scale independently but require duplicated isolation, deletion and residency enforcement; defer until measured need and a superseding ADR. ANN query plans must be tested to ensure authorization prefilter semantics and acceptable recall; do not broaden scope to improve recall. Source deletion/revocation invalidates embeddings/cache and pending retrieval. Contract: INTEGRATION_AI_SPEC.md and SECURITY_ARCHITECTURE.md. Verify cross-tenant nearest-neighbour sentinel, scope revocation, purge and fallback behavior.
