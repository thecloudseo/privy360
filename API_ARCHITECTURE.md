# API architecture and domain contracts

## Common protocol (normative for every endpoint below)

JSON REST `/api/v1`; OpenAPI 3.1 contract-first, additive compatible changes, explicit `/v2` for breaking semantics. UTF-8; ISO 8601 UTC timestamps and UUID IDs; no bigint precision loss (sequences serialized as decimal strings). NestJS is the domain API. Next.js BFF only translates secure sessions into authenticated internal calls; service clients use narrowly scoped OAuth client credentials. Graph access is bounded query templates, not unrestricted GraphQL/SQL.

Authentication classes: **S** staff OIDC/BFF session, **D** verified Data Principal portal session, **C** scoped service account, **P** separate platform operator audience, **U** anonymous published content only. All T resources resolve tenant from TrustedContext; S/C tenant membership is checked server-side, D tenant and principal are bound to session. U hostname selects published tenant only through verified domain registry. No `tenant_id`, `created_by`, `approved_by`, owner escalation or policy override in write DTOs. Payload tenant fields are rejected, not trusted. Global law reads use published corpus only; publishing requires separate global corpus grant, not Tenant Admin.

List GET accepts cursor (opaque signed scope/filter-bound), limit 1..100 (25 default), allowlisted sort/filter, optionally asOf/knownAt. Returns `{items:[Resource],nextCursor,watermark?}`. Resource response includes id, version, timestamps, allowed fields and typed relationship IDs; never secrets or raw private source data by default. Object/list/count/search/export enforce the same object/field scopes before pagination. GET by inaccessible ID returns non-disclosing 404. Unauthenticated =401, denied action=403, validation=422, optimistic conflict/idempotency mismatch=409, stale If-Match=412, throttled=429 with Retry-After. Errors `{type,title,status,code,correlationId,fieldErrors?}`; no stack traces or existence leaks.

Create returns 201 + Location + Resource; transition/update returns 200 + Resource/new version; asynchronous work returns 202 `{jobId,state,statusUrl}`. PATCH uses explicit allowlisted DTO (not arbitrary JSON Patch) and If-Match required. State transitions use POST commands `{expectedVersion,reason?,...commandFields}`. DELETE means archive where offered; destructive erasure only through Deletion workflow. Never imply archive erases historical evidence.

All POST/PATCH/DELETE commands require `Idempotency-Key` (UUID/random 128-bit token). Key scope = trusted tenant+actor+route; canonical request hash mismatch returns 409; concurrent same key serialized; committed original result returned on retry. Initial API result cache 24h, with permanent business uniqueness/receipts for consent, deletion, notification and external effects beyond cache expiry. Authenticate/authorize retries again; revoked access does not retrieve a prior sensitive response. GET is side-effect free except access audit. Request size defaults 1 MiB JSON; files separate. No client-provided SQL/predicate expressions.

Every mutation produces `<Domain>.<Resource>.<Action>` audit using actual command; sensitive reads/downloads/exports, authorization denials and approval decisions also audited. All commands validate FK ownership, version/state guards, bounded text/enums and classification. Authentication, authorization, tenant resolution, common contracts, validation, idempotency and audit rules in this section apply to EACH row, with refinements below. No endpoint is exempt because a row omits repeated text.

## Privacy Centre public and subject API

Same NestJS domain services under `/api/v1/portal`; isolated audience and origin. U GET `/config`, `/notices`, `/notices/:publishedVersionId`, `/contact` returns published allowlisted fields for verified hostname only; cache by tenant+locale+publication version. No staff drafts/counts/principal lookup exposed. D GET/POST `/requests`, GET `/requests/:id`, GET `/requests/:id/responses/:responseId`, POST `/grievances`, POST `/nominations`, GET/POST `/consent-events`, GET/PATCH `/preferences` operate on session principal only. No principalId parameter; delegation uses server-verified grant ID scoped to action. Request body `{type,description,activityRefs?,attachmentVersionIds?}` → tracking code/id/state; every attachment must belong to that subject's reservation. Anonymous callers may view notices/contact, not case status. Sign-in/verification endpoints use enumeration-resistant generic responses, rate budgets and proof expiry; raw OTP is never logged/persisted in product tables.

## Inbound/outbound webhooks and SDK

Inbound `/api/v1/inbound/:registrationId` accepts provider signature (HMAC/asymmetric/mTLS per adapter), timestamp tolerance (proposed 5 minutes), event ID and schema version. Registration resolves trusted tenant; reject signature/replay before creating work. Persist inbox receipt and enqueue atomically; return 202 promptly; payload tenant ignored/rejected. Outbound envelope signs exact canonical bytes with tenant connection key, key ID, timestamp, event ID and delivery ID; secret rotation overlaps valid keys briefly under approved policy. Destination egress checked at registration and each connection/redirect. Replay is a separate audited command, not resetting event identity.

Consent SDK is a thin versioned client: configuration, display published notice, gather explicit event, submit proof/idempotency key, return receipt. It contains no privileged secret or tenant authorization decision. Browser origin allowlists prevent unintended embedding but are not authentication. Server collection clients must provide verifiable subject/session proof; possession of a principal UUID is insufficient.

## Contract verification and compatibility

Each implementation ticket must deliver machine-readable OpenAPI and examples for its precise operation before controllers; schema lint, generated client compile, provider/consumer tests, all role/tenant negatives, pagination/scope tests, concurrent retries and redaction tests are mandatory. This document freezes semantics; machine-readable files are subsequent contract tickets, not permission to invent domain decisions. Deprecation requires published overlap, usage measurement and customer migration; breaking event/API changes never silently replace deployed contracts.

## Binding refinements

Contact/content/payload references are typed protected_payloads IDs owned by the same tenant/root object. Public API never dereferences arbitrary caller URLs. Actor IDs come from actor_refs via trusted identity, not body fields. Principal session binding is principal_bindings with verified issuer/subject and assurance. Background operations distinguish USER_DELEGATED (current originating actor permission required) from SYSTEM_POLICY (separately approved, narrowly scoped service grant plus pinned policy and current tenant/hold checks); a scheduled policy is not a perpetual user token.

Partial publication/configuration and contract scaffolds must not expose active business mutation routes until AUDIT-001/002 are integrated. Earlier identity/grant tickets may run only in isolated test harnesses with the audit port stub; enabled deployments require durable audit wiring. No runtime “skip audit” flag. Regulatory corpus intake is specified in REGULATORY_INGESTION_SPEC.md; connector/AI protocols in INTEGRATION_AI_SPEC.md.
