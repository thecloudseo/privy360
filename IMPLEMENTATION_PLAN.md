## Steps and acceptance mapping

1. **Quality and reproducibility.** Extend .github/workflows/foundation.yml with least-privilege permissions and explicit quality results for frozen install, formatting, ESLint, TypeScript, unit tests, contract/structure validation and build. Modify package.json only for ticket-specific scripts and pinned test tooling; update pnpm-lock.yaml. No application, database, API, authorization, tenant, audit or regulatory contract changes. Acceptance: ESLint/typecheck/unit jobs report explicit results.
2. **Synthetic browser harness.** Add pinned Playwright test dependency/config and a fixture-only browser test under tests/e2e. Use generated synthetic DOM, no server, user data, product screen or endpoint. CI installs Chromium and runs the test; failures stop the job. Acceptance: Playwright harness reports a real pass/fail result. T4 business journeys/accessibility are inapplicable because there is no UI implementation.
3. **Security gates.** Add dedicated CI jobs for Semgrep, CodeQL, Trivy filesystem vulnerability scan, Gitleaks, pnpm audit, Checkov and CycloneDX SBOM generation. Configure each to fail on actionable findings and retain machine-readable output where feasible. Trivy container scanning is explicitly inapplicable until an image exists; Checkov reports no-IaC status until IaC exists. CI uses read-only token permissions except CodeQL's required security-events: write; no production credentials. Acceptance: every named tool reports explicit status, no silent skips.
4. **Negative gate fixtures.** Add synthetic tests that create temporary canary secret and vulnerable dependency fixtures, run the corresponding scanner/gate, and assert nonzero exits. Keep fixtures out of tracked source and logs; never install vulnerable code as a runtime dependency. Add deterministic checks of the gate configuration so missing scans fail. Acceptance: injected secret and vulnerable fixture fail appropriately.
5. **Verification and self-review.** Run frozen install, format, lint, typecheck, unit, Playwright, build, structure, audit and applicable local security scanners; compare CI workflow against every tool in the ticket. Record unavailable local scanners separately from CI results. Review changes for scope, secret exposure, excessive CI permissions, dependency risk and bypasses. T1 is inapplicable: no schema or migration; T2: no API/domain change; T3: no worker/external effect; T4: harness only, no UI; T5 production human/security approval remains a later gate. No OPEN decision is self-approved.
